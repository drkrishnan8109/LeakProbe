The task

From unusual readings to a useful investigation

Pressure or flow changes can have several explanations. A leak is one possibility; changes in demand, operations, or sensor behavior can also affect readings.

This demo asks: Which simulated scenarios best fit the evidence, and what reading could help distinguish them?

The code ranks scenarios. The LLM coordinates the investigation and explains uncertainty.

Network model · key terms

What WNTR, EPANET, and Net3 mean

WNTR

Water Network Tool for Resilience. An EPANET-compatible Python package for simulating water networks and analyzing their resilience.

EPANET

U.S. EPA software used to model drinking-water distribution systems, including hydraulic behavior and water quality.

Net3

“EPANET Example Network 3,” a reference network distributed with WNTR examples. Net3 is the model’s name, not “EPANET version 3.”

Benchmark network

A reference network used to develop and compare analysis methods. This model does not represent a specific city’s water system.

Tool calls · what they mean

Python runs each allowlisted tool

get_observations()

Returns noisy pressure and flow time series for the selected case.

get_network()

Returns model size, installed sensors, candidate pipes, optional gauge points, and remaining time.

get_operation_records()

Returns operation notes; the Net3 benchmark currently has none.

compare_hypotheses()

Scores normal and candidate leak scenarios. A weak top leak fit can be rejected as uncertain; scores are not probabilities.

recommend_measurement()

Uses predicted pressure spread among leading fits to suggest a feasible unmeasured point.

collect_demo_measurement(point)

Reveals a stored pressure reading and deducts 10 minutes from the budget.

The reading is a fixture from simulation, not a real field visit.

Held-out result · full observations

Fewer false alarms, more missed leaks

The detector ranks simulated patterns by normalized RMSE. Lower is a closer fit. The score is not a probability.

Decision rule

When a leak scenario ranks first but its score exceeds 64.2958, return uncertain instead of a leak alarm.

The cutoff was selected on 400 development cases. It is specific to the full-observation dataset.

38 of 100 were uncertain; binary metrics count these as no leak alarm.

100 held-out cases · 80 leak, 20 normal

Before cutoff: TP/FN/FP/TN = 61/19/12/8
Recall 76.2% · specificity 40%

With cutoff: TP/FN/FP/TN = 32/48/3/17
Recall 40% · specificity 85%

Balanced accuracy: 58.1% → 62.5%
Exact pipe across leak cases: 41/80 → 26/80

This conservative setting raises specificity but reduces leak detection. Results are generated benchmark measurements, not field performance.
